## Actual use, coordination and resources

Customer Zero was Runtime's own project/development work: reporting JSONL execution
status/usage and verifying evidence file manifests. Both are standard-library CLIs,
not extra demonstration documents. Behavioral contracts, isolated examples and
regression tests fit these bounded code tasks; native replay/negative fixtures
qualified the uncertain engine transitions. Symphony was evaluated first, then
rejected for durability/provider-boundary needs (D011/D012); no replacement generic
scheduler was built. Temporal supplies durable history, signals and activity state.

The chain driver created/reviewed accepted inputs and corrected concrete supporting
defects. Owner decisions concerned repository visibility and existing access; the
owner did not relay prompts between executors. After the report continuation signal,
Runtime performed both executor steps, test gates, independent review and protected
merge. The evidence task needed one submission. Actual coordination, all measured
provider usage and unknown monetary/chain-driver totals are detailed in the two
linked task reports. No new subscription, API billing or external permission was
introduced. Per-call bounds are operational safeguards, not an invented project cap.

## Start, resume and hand over

Use [the runbook](runbook.md) for the exact local environment and commands. Begin with
[the plan](plan.md), inspect Git and recorded process identities, and confirm old
writers stopped. Both existing tasks are completed: `--resume` inspects them;
resubmission and access-restored signals are inappropriate. Do not delete state to
make submission succeed. New work requires its own accepted task/brief and separately
reviewed host verifier before Runtime starts implementation.

The final compressed native database and integrity hashes are in
[evidence/v0.1](../evidence/v0.1/). Local .runtime task directories retain frozen input,
old/current candidate and immutable Git candidates. Source, candidate bundles,
raw events, acceptance/review receipts and task histories are preserved in Git.
Credentials are intentionally absent. A fresh session on this workstation can
continue from the project; restoring another workstation also requires its own
qualified subscriptions, binaries and careful reconstruction from saved artifacts.
This release does not claim a tested one-command disaster restore to another host.

## Limits of the qualified route

- Trusted single local Mac (macOS26.3 arm64), loopback development Temporal, one worker
  activity at a time. No production deployment, cloud service or multi-user isolation.
- Explicit regular tools/ source files in Nortropic/nortropic-runtime; no arbitrary
  repository/language or general hostile-host guarantee. Claude only has native
  Read/Edit/Write; Codex/test/reviewer execution uses the qualified native sandbox.
- Bound process groups and abrupt worker death were tested. Arbitrary guardian
  SIGKILL, deliberately detached hostile descendants and host compromise were not.
- Known supplied capacity/access waits persist. Automatic weekly quota discovery
  and actual vendor quota exhaustion were not tested; failures never trigger blind
  automatic model retries. Review rejection waits for operator diagnosis rather than
  an automatic repair loop. Ambiguous publication requires inspected reconciliation.
- GitHub required contexts/strict base/admin/linear protection are active. This plan
  accepts status writers from any app; host publication credential isolation matters.
- Report status is deliberately conservative about failed tool items and is distinct
  from candidate/task acceptance. Reported token/cache/list-price fields are retained;
  subscription monetary attribution and root-session total usage are unknown.
- v0.1 covers these tasks and conditions. Further business features or continuous
  self-improvement require another applicable accepted task.
